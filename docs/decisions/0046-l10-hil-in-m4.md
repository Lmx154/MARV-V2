# 0046: L10 HIL in M4: tick rounding, the N-tick delay, priorities, arming, outputs

## What changed

Architect ruling for quad §4.0 M4's L10 HIL (2026-10-17); no frozen test changes.

1. The gz plugin accepts a tick that is not whole ns: host step = round(m · tick) ns; the plant integrates at it through
   the adapter's t_true; the firmware keeps the exact rational; the run report states the error (fc3v2: −1.6 ppm) and it
   is at most the profile's odr_error. A whole-ns tick is unchanged byte for byte. Frozen tests extended (HIL S2a, nothing
   loosened): `tests/regression/quad/L06/gz/test_sensor_clock.py` (gz runs at the fc3v2 tick, m = 1 and 2; the whole-ns
   byte-identity control; the odr_error threshold control; refusals) and `tests/regression/quad/L06/tools/test_world_sensors.py`
   (the generator's rounded step and its odr_error element).
2. SIL and HIL apply the command of tick j − N at tick j (the adapter's delay line, N = 0 default). N ≥ F + the measured
   USB turnaround, and N ≤ N_max, the largest N for which every configuration row at the card's nominal J and τ (all notch operating points, latency 3 + N samples, flight f32 gains) meets QF-3: PM ≥ PM_min and M_s ≤ Ms_max (tools/card/hil_delay_margin.py). The robustness-box corners are left out because a HIL or SIL run's plant is the card's nominal model (perfect-model, core §6); the worst-corner rule gives N_max = 0 by construction (the gain rule puts that corner at PM_min: 45.0045° at N = 0, tests/regression/quad/L09/results/hil_s2/hil_delay_margin.txt). Every HIL run report states N, the nominal rows' PM and M_s, and the worst-corner shortfall, labelled "not a margin result". If N_max is below the link's required N, the choice (decimation or a floor) is Luis's.
   Implemented (HIL S2b-a, nothing loosened): `<command_delay_ticks>` N in the world (default 0, at most 256), the adapter's
   delay line; the plant is stepped at tick j with the SIL's command of tick j − N, the stop command (DShot 0) before that;
   N = 0 is byte-identical. Frozen tests extended: `tests/regression/quad/L06/adapter/clock_test.cpp` (the N-tick shift
   against an N = 0 run of the shifted stream; N = 0 bitwise; the bound), `tests/regression/quad/L06/gz/test_sensor_clock.py`
   (gz runs at N = 3, m = 1 and 2; the N = 0 byte-identity control; refusals) and
   `tests/regression/quad/L06/tools/test_world_sensors.py` (the generator's element, N = 0 unchanged, refusals).
3. The HIL image is quad_fc with the fc3v2 table unchanged (hash handshake); composition::tick runs in a software IRQ at
   the IMU priority, k ticks per frame; no frame for D_HIL is an IMU deadline miss (disarm); EMB-3 = a frame's k ticks
   plus USB handling within k tick periods.
4. Arming is the real radio on the board clock; the SIL ABI gains ManualControl staging to replay the HIL sticks with
   their frame ages.
5. The HIL images load no DShot program and drive no motor pad (not even stop frames); the ESC is unpowered; the flight
   ELF has no HIL symbol.
6. Spec (Luis): quad §1 line 42 "HIL (L10) is deferred until after first flight" becomes "L10's MVP subset is built in
   M4 before first flight (Luis, 2026-10-17); it rehearses the firmware and radio path and does not gate the flight";
   L10 "Needs from the ground segment" gains "MVP: a bench-only framed USB link; IF-9 with the ground segment"; L10's
   comparison line gains "with the stated N-tick command delay in both".

Stages: S1 bench-only USB link image (both directions' throughput, round-trip p99, D_HIL, F, N checked against N_max);
S2 SIL: quad_fc as a SIL library at the fc3v2 tick (item 1), stick staging (item 4), N-delay (item 2), a gz run that arms
from a stick script and hovers in angle mode, existing gz suites byte-identical at N = 0; S3 HIL open loop: a recorded
SIL sample stream replayed to the board gives the SIL's DShot within float tolerance (-ffp-contract=off both), EMB-3
reported; S4 HIL closed loop with gz: Luis arms with the RadioMaster and hovers the sim in angle mode, radio off disarms
at 1.5 s; S5 T6: S4's sticks replayed into SIL agree within float tolerance, frozen as the L10 comparison scenario.

## Why

gz-sim steps a fixed whole number of ns; a per-tick USB round trip at 7.5 kHz cannot be made, so the delay must be
explicit and equal in both runs for traces to agree; HIL must fly the flight configuration; preemption must match
flight for EMB-3 to mean anything; AM32 arms on zero-throttle frames.
